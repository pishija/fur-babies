# Feature: Virtual AI Friend

## Overview

Every dog gets an AI virtual friend the moment their profile is created. The friend has a name and personality generated from the dog's breed and always speaks as if it knows the specific dog personally — because it does. It reads the dog's profile (breed, age, sex, weight, neutered status) and health calendar to give personalised, calibrated responses. It also sends proactive messages unprompted when health events are coming up or overdue. The chat lives in its own dedicated tab in the app's tab bar and switches automatically when the owner switches dogs.

---

## Screens

1. **AI Friend Chat** — the main iMessage-style conversation screen for the active dog's AI friend

No other standalone screens. The tab always shows the chat for whichever dog is currently active.

## AI Friend Chat

### Purpose
Let owners have a natural conversation with a breed-aware AI companion about their specific dog. All messages are persisted so the history is always available.

### UI elements
- **Navigation bar**: AI friend's name on the left, small avatar icon; active dog's name as subtitle
- **Message list**: scrollable, newest messages at the bottom
  - Owner messages: bubble on the right (filled, primary colour)
  - AI friend messages: bubble on the left with a small circular avatar of the AI friend
  - Proactive nudge messages from the AI appear the same as regular AI messages — no special treatment needed
  - Timestamps shown between message groups when there is a gap of more than 1 hour
- **Typing indicator**: animated dots on the left while the AI is generating a response
- **Text input bar** at the bottom: text field + send button; send button disabled when input is empty
- **Welcome message**: the very first message in every new chat is from the AI friend, auto-sent when the dog profile is created

### States
- **Loading history**: skeleton bubbles while past messages load
- **Empty (impossible in practice)**: the welcome message is always present, so this state should not occur; if it does (edge case), show the welcome message placeholder
- **Populated**: scrollable message history
- **AI generating**: typing indicator visible after user sends a message; input bar disabled until response arrives
- **Error sending**: user's message bubble shows a red "!" retry button; AI does not respond until the message is successfully sent
- **Network offline**: banner shown at top "No connection — messages will send when you're back online"; input still allowed, queued locally

### User actions
- Type a message and tap Send → message sent to AI, typing indicator appears, AI response streams in
- Scroll up → loads older message history (pagination)
- Tap the retry button on a failed message → resends that message
- Switch active dog (via dog switcher in tab bar) → chat tab reloads showing that dog's AI friend and history

## AI Friend Personality

### Name generation
The AI friend is given a name when the dog profile is first created. The name is generated by a Firebase Cloud Function based on the dog's breed personality category:

| Breed category | Personality type | Example name style |
|---|---|---|
| High-energy (Border Collie, Husky, Jack Russell) | Energetic, curious, playful | Bolt, Zara, Spark |
| Gentle giant (Great Dane, Newfoundland, Saint Bernard) | Calm, wise, reassuring | Bruno, Sage, Bear |
| Companion breeds (Cavalier, Poodle, Bichon) | Warm, sociable, encouraging | Lily, Coco, Milo |
| Working breeds (German Shepherd, Rottweiler, Malinois) | Confident, structured, protective | Rex, Hera, Atlas |

- The name is stored in Firestore and never changes
- The owner cannot rename the AI friend

### Context injected into every message
Every message the owner sends is answered with the following dog context always available to the AI:
- Dog's name, breed, sex, age (calculated from birthday), weight, neutered status
- Last 5 health events (type, date, completed or pending)
- Upcoming health reminders within the next 30 days

This context is assembled at send time, not stored in the chat history.

### Topics the AI can handle
- **Nutrition**: daily portion sizes, toxic foods to avoid, breed-specific dietary needs
- **Health**: symptom checking, what to watch for by breed, seasonal care
- **Training**: breed-specific training methods, common behavioural problems
- **Heat cycles**: what to expect, fertile window, false pregnancy warning signs (only relevant for intact female dogs)
- **Travel**: regulations, preparation, calming techniques
- **General**: any free-form question about the specific dog

### Proactive nudges
The AI friend sends messages without being prompted when triggered by health calendar events:
- 4 weeks before a health event is due: a gentle reminder message
- 1 week before: a standard reminder with more detail
- 1 day before: an urgent prompt
- When a health event becomes overdue: an alert message

These are generated by a Firebase Cloud Function that fires on the same schedule as push notifications. The message appears in the chat as a regular AI friend message.

Example: *"Luna's rabies booster is due in 3 weeks — want me to help you prepare for the vet visit?"*

## User Flows

### Flow 1: Dog profile created → welcome message appears
1. Owner saves a new dog profile
2. Firebase Cloud Function generates the AI friend (name + personality)
3. Welcome message is written to Firestore as the first message in the chat
4. Owner navigates to the AI Friend tab → welcome message is already there

### Flow 2: Owner sends a message
1. Owner types a question and taps Send
2. Message appears immediately as a bubble on the right
3. Typing indicator (animated dots) appears on the left
4. Message is sent to the AI with the dog's full context injected
5. AI response streams back and appears as a bubble on the left
6. Typing indicator disappears once the response is complete
7. Both messages are saved to Firestore

### Flow 3: Switch dogs mid-conversation
1. Owner is in the AI Friend tab for Dog A
2. Taps Dog B's avatar in the dog switcher
3. Chat tab instantly transitions to Dog B's AI friend — different name, different history
4. Dog A's conversation is untouched

### Flow 4: Proactive nudge received
1. Health event for Luna is due in 7 days
2. Cloud Function runs and writes a nudge message to the chat as an AI friend message
3. A push notification is also sent (handled by Notifications — not this feature)
4. Owner opens the AI Friend tab → sees the nudge message as the most recent message
5. Owner can reply to start a conversation about the upcoming event

## Business Rules

- **One AI friend per dog** — created automatically, cannot be created manually, cannot be deleted independently of the dog
- **Welcome message is always the first message** — written by the Cloud Function at dog creation time; if it fails, it retries up to 3 times silently
- **Message history is unlimited** — no cap on stored messages; pagination loads in batches of 30
- **AI responses are not editable or deletable** by the owner — the conversation is a permanent log
- **Owner messages cannot be deleted** either — the full history is preserved
- **The AI does not retain memory between sessions beyond what is in Firestore** — it reads the message history (last N messages for context window) and the dog's live profile on every send
- **Streaming responses**: the AI response should stream token by token into the bubble as it arrives, not appear all at once
- **If the AI returns an error**: show the typing indicator for a moment, then display a friendly error message in a bubble: *"Sorry, I'm having trouble connecting right now. Try again in a moment!"* — this message is NOT saved to Firestore

## Data (Firestore)

```
users/{userId}/dogs/{dogId}/virtualFriend/{friendId}
  name: string
  personalityType: "energetic" | "calm" | "warm" | "confident"
  createdAt: timestamp

users/{userId}/dogs/{dogId}/virtualFriend/{friendId}/messages/{messageId}
  role: "user" | "assistant"
  content: string
  createdAt: timestamp
  isProactiveNudge: boolean   // true if sent by Cloud Function, not by owner
```

**Reads:** Chat screen (message history, paginated), Cloud Function (last N messages for context)
**Writes:** Owner send action (user message), AI response (assistant message), Cloud Function (proactive nudge messages, welcome message)
**Deletes:** Only when the parent dog profile is deleted (cascading delete)

## Edge Cases

| Scenario | Behaviour |
|---|---|
| AI friend Cloud Function fails at dog creation | Retried up to 3 times; if all fail, the chat tab shows an error state "We couldn't set up your AI friend. Pull to refresh." with a manual retry button |
| Owner switches dogs while AI is generating a response | Response for the previous dog is discarded; the new dog's chat loads |
| No internet when owner sends a message | Message queued locally with a "Pending" indicator; sent automatically when connection restores |
| AI response takes > 10 seconds | Typing indicator stays visible; no timeout on the user's end (AI responses for complex health questions can be lengthy) |
| Owner sends an empty message | Send button is disabled — not possible |
| Dog has no health events yet | AI still works normally; no proactive nudges are sent until health events are added |
| Intact female dog receives heat cycle nudges | Only triggered if `isNeutered = false` and `sex = "female"` |
| Owner asks about a topic outside dog care | AI gracefully redirects: stays in character and brings the conversation back to the specific dog |

## Out of Scope

- The owner cannot change the AI friend's name or personality
- There is no voice message support
- There is no image sending (owner cannot send photos to the AI)
- Vet-share PDF export — v2.0 feature, not in this version
- Persistent memory referencing conversations from months ago — v2.0 feature; current version reads last N messages for context only
- Push notifications for proactive nudges — handled in the Notifications feature
