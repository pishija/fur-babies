# Feature: Push Notifications

## Overview

Push notifications keep owners engaged with their dog's health, matches, and events without requiring them to open the app. Notifications are delivered via Firebase Cloud Messaging (FCM) → APNs. Each category can be independently toggled in the Notification Settings screen (Me tab). The app requests permission immediately after the owner creates their first dog profile. All notification taps deep-link into the relevant screen.

---

## Permission Request

### When it's shown
Immediately after the owner completes their first dog profile. The system permission prompt appears as the dog profile is saved and the app transitions to the main tab bar for the first time.

### Flow
1. Owner taps "Save" on the Create Dog screen
2. Dog profile saved to Firestore
3. App transitions to main tab bar
4. `UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .badge, .sound])` is called
5. iOS system alert appears: "FurBabies would like to send you notifications" — standard iOS prompt, no custom pre-prompt
6. Owner grants or denies
7. Result stored — if denied, the Notification Settings screen shows the OS-level banner with a "Go to Settings" deep link

### Rules
- Permission is requested exactly once at this point — not on first launch, not on sign-up
- If the owner denies, all notification toggles in Notification Settings remain visible but greyed out with explanatory text; no notifications are sent
- If the owner later grants permission from iOS Settings, the toggles become active and notifications resume
- The FCM token is registered and stored in `users/{userId}.fcmToken` after permission is granted

## Notification Categories

### 1. Health Reminders

Gentle escalating reminders for upcoming health events (vaccinations, worming, flea treatment, vet checks, etc.).

| Urgency | When sent | Title | Body |
|---|---|---|---|
| Gentle | 4 weeks before due | "{{dogName}}'s health check is coming up" | "{{eventType}} is due in 4 weeks. Tap to view the health calendar." |
| Standard | 1 week before due | "{{dogName}} is due for {{eventType}} soon" | "Don't forget — {{eventType}} is due in 7 days." |
| Urgent | 1 day before due | "{{dogName}}'s {{eventType}} is due tomorrow" | "{{eventType}} is due tomorrow. Tap to mark it complete or reschedule." |

**Deep link:** `furbabies://health-calendar?dogId={{dogId}}&eventId={{eventId}}`  
**Trigger:** Cloud Function scheduled when a health event is created or updated  
**Toggle:** `healthReminders`

---

### 2. Overdue Health Alerts

Alert when a health event passes its due date without being marked complete.

| When sent | Title | Body |
|---|---|---|
| Day after due date | "{{dogName}}'s {{eventType}} is overdue" | "{{eventType}} was due yesterday. Tap to update {{dogName}}'s health record." |

**Deep link:** `furbabies://health-calendar?dogId={{dogId}}&eventId={{eventId}}`  
**Trigger:** Cloud Function scheduled job runs daily; checks for health events where `dueDate < now` and `completedAt == null` and no overdue notification has been sent  
**Toggle:** `overdueAlerts`

---

### 3. AI Friend Nudges

Proactive messages from the virtual AI friend to re-engage owners who haven't opened the chat recently.

| When sent | Title | Body |
|---|---|---|
| 48h after last message (if no new message) | "{{dogName}}'s AI friend has something to say" | "{{nudgeText}}" — generated by Cloud Function using the dog's context |

**Deep link:** `furbabies://ai-friend?dogId={{dogId}}`  
**Trigger:** Cloud Function checks last message timestamp per dog; generates a context-aware nudge via Claude API and sends it  
**Frequency:** At most once per 48 hours per dog; no nudge if the owner has been active in the last 24 hours  
**Toggle:** `aiFriendNudges`

---

### 4. Match Alerts

Notification when a mutual match occurs (both dogs have liked each other).

| Title | Body |
|---|---|
| "{{dogName}} has a new match! 🐾" | "You and {{otherDogName}} liked each other. Start a conversation!" |

**Deep link:** `furbabies://matches?matchId={{matchId}}`  
**Trigger:** Cloud Function fires when a `matches/` document is created (mutual match detected in swipe write path)  
**Toggle:** `matchAlerts`

---

### 5. New Messages

Notification when a matched owner sends a conversation message.

| Title | Body |
|---|---|
| "{{ownerName}} sent you a message" | "{{messagePreview}}" — first 80 characters of the message text |

**Deep link:** `furbabies://conversation?matchId={{matchId}}`  
**Trigger:** Cloud Function fires on new document in `matches/{matchId}/messages/`; does not fire if the recipient has the conversation open (presence check via Firestore)  
**Toggle:** `newMessages`

---

### 6. Event Updates

RSVP confirmations and reminders for saved events.

| Trigger | Title | Body |
|---|---|---|
| Immediately on RSVP | "You're going to {{eventName}}" | "You've RSVP'd as Going. We'll remind you closer to the date." |
| 1 day before event | "{{eventName}} is tomorrow" | "Don't forget — {{eventName}} starts tomorrow at {{time}}." |
| Event cancelled | "{{eventName}} has been cancelled" | "This event has been cancelled by the organiser." |

**Deep link:** `furbabies://event-detail?eventId={{eventId}}`  
**Trigger:** Cloud Function fires on RSVP write, on event cancellation, and on a scheduled job for day-before reminders  
**Toggle:** `eventUpdates`

---

### 7. Exhibition Reminders

Reminder notification for watchlisted exhibitions, sent the chosen number of days before the event.

| Title | Body |
|---|---|
| "{{exhibitionName}} is in {{N}} days" | "{{exhibitionName}} starts on {{date}} in {{city}}. Don't forget to register." |

**Deep link:** `furbabies://exhibition-detail?exhibitionId={{exhibitionId}}`  
**Trigger:** Cloud Function scheduled job; reads `remindAt` timestamp on `users/{userId}/watchlist/{exhibitionId}` documents and fires when `remindAt <= now` and `reminderSentAt == null`; sets `reminderSentAt` after sending  
**Toggle:** `exhibitionReminders`

---

### 8. Badge Earned

Notification when a new badge is unlocked. Not sent for badge revocations.

| Title | Body |
|---|---|
| "{{dogName}} earned a new badge!" | "{{badgeName}} — {{badgeDescription}}" |

**Deep link:** `furbabies://dog-profile?dogId={{dogId}}&section=badges`  
**Trigger:** Cloud Function fires when an `earnedBadges/` document is written for a dog  
**Toggle:** `badgeEarned`

---

### 9. Walk Streak

Daily reminder to go for a walk. **Off by default** — owner must opt in.

| Title | Body |
|---|---|
| "Time to walk {{dogName}}!" | "Keep the streak going — {{dogName}} is waiting for their walk." |

**When sent:** Daily at the time of the owner's most recent walk session (or 10:00 local time if no walk history)  
**Deep link:** `furbabies://map`  
**Trigger:** Cloud Function scheduled daily; checks streak status and sends if the day's walk hasn't happened yet (36-hour streak window)  
**Toggle:** `walkStreak` (default: false)

## FCM Integration

### Token management

```
users/{userId}
  fcmToken: string | null      // updated on each app launch if changed
  fcmTokenUpdatedAt: timestamp
```

- The FCM token is refreshed by Firebase SDK automatically. The app listens for token refresh events and updates `users/{userId}.fcmToken` in Firestore.
- Cloud Functions read `fcmToken` from the user document before sending — if null, no notification is sent.
- On sign-out, `fcmToken` is set to null to prevent notifications reaching the wrong device.

### Sending from Cloud Functions

All notification sends go through a shared Cloud Function utility:

```
sendPushNotification(userId, title, body, deepLink, category)
  → reads users/{userId}.fcmToken
  → checks users/{userId}/notificationSettings.{category}
  → if token exists and category is enabled → sends via FCM Admin SDK
  → if token is null or category is disabled → no-op
```

### Notification payload

```json
{
  "notification": {
    "title": "...",
    "body": "..."
  },
  "data": {
    "deepLink": "furbabies://...",
    "category": "healthReminders"
  },
  "apns": {
    "payload": {
      "aps": {
        "sound": "default",
        "badge": 1
      }
    }
  }
}
```

### Handling notification tap in the app

- The app registers a `UNUserNotificationCenterDelegate`
- On tap: `userNotificationCenter(_:didReceive:withCompletionHandler:)` extracts `deepLink` from `userInfo["data"]`
- Calls `AppRouter.open(URL(string: deepLink)!)` to navigate to the correct screen
- Deep link navigation is only active when the app is in the `.authenticated` state; if the session has expired, the deep link is discarded and the auth screen is shown

## Notification Settings Persistence

```
users/{userId}/notificationSettings
  healthReminders: boolean     // default: true
  overdueAlerts: boolean       // default: true
  aiFriendNudges: boolean      // default: true
  matchAlerts: boolean         // default: true
  newMessages: boolean         // default: true
  eventUpdates: boolean        // default: true
  exhibitionReminders: boolean // default: true
  badgeEarned: boolean         // default: true
  walkStreak: boolean          // default: false (opt-in)
```

- The `notificationSettings` document is created with defaults when the owner's `users/{userId}` document is first created (during Owner Profile Setup)
- All Cloud Functions check the relevant flag before sending — if the document or field is missing, the notification is sent (fail-open, defaults are all-on)

## Edge Cases

| Scenario | Behaviour |
|---|---|
| Owner denies OS-level permission | FCM token still registered but APNs silently drops all notifications; no error surfaced to the app |
| FCM token changes (app reinstall, token refresh) | App updates `fcmToken` in Firestore on next launch; old token ignored by FCM |
| Owner signed out | `fcmToken` set to null; no notifications sent to the device |
| Dog deleted | Any pending Cloud Function notifications for that dog's health events, walk streak, or badges are skipped if the dog document no longer exists |
| Owner has multiple devices | Only the most recently updated FCM token is stored — notifications go to the last active device |
| Notification fired for an overdue event that was just marked complete | Cloud Function checks `completedAt` before sending; if already completed, skips |
| Nudge fires during active AI chat session | Cloud Function checks `lastSeen` timestamp on the AI conversation; if owner is active, nudge is suppressed |
| Health event rescheduled after reminders are already queued | Old Cloud Function scheduled tasks are cancelled and new ones created when the due date changes |

## Out of Scope

- In-app notification centre / inbox — not in v1; notifications exist at OS level only
- Rich notifications (images, action buttons) — not in v1
- Per-dog notification toggles — settings are per-owner account, not per dog
- SMS or email notifications — push only in v1
- Quiet hours / do-not-disturb settings — not in v1; relies on iOS Focus modes
- Notification analytics — not in v1
